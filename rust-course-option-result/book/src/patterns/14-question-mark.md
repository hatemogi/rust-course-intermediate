# 반환 타입에 맞춰 ? 쓰기

앞 장에서는 `.ok()`와 `ok_or`로 `Option`과 `Result`를 서로 바꾸었습니다.
이번에는 이 변환을 `?`와 연결해, 값이 있으면 다음 작업을 계속하고 값이 없거나
오류가 나면 함수에서 바로 반환하는 코드를 작성합니다.

`?`를 쓸 때는 현재 함수의 반환 타입을 먼저 확인하세요. `?`가 `Option`과
`Result`를 자동으로 바꾸어 주지는 않습니다. 먼저 두 타입 사이의 변환을 살펴본 뒤,
같은 `Result`라도 오류 타입이 다를 때는 어떻게 처리하는지 알아봅니다.

## Option을 반환하는 함수에서 ? 쓰기

`Option`을 반환하는 함수에서는 `Result`에 `?`를 바로 붙일 수 없습니다.
실패 이유를 버려도 괜찮다면 `.ok()`로 `Option`으로 바꾼 뒤 `?`를 사용할 수 있습니다.

다음 함수는 입력을 포트 번호로 읽을 수 있을 때만 접속 주소를 만듭니다.
호출하는 쪽에서는 주소를 얻거나 얻지 못했다는 사실만 알면 되고, 실패 이유까지는
필요하지 않다고 가정합니다.
타입이 바뀌는 과정을 설명하기 위해 변환과 값 꺼내기를 여러 줄로 나누었습니다.

```rust
{{#rustdoc ../../../examples/14_question_mark.rs item=address_if_valid}}
```

`parse::<u16>()`은 `Result`를 반환합니다. `.ok()`는 `Ok(8080)`을 `Some(8080)`으로,
`Err(error)`를 `None`으로 바꿉니다. 그다음 `?`는 `Some`에서 포트 번호를 꺼내거나,
현재 함수에서 `None`을 바로 반환합니다. `None`이면 주소를 만드는 마지막 줄은
실행하지 않습니다.

따라서 `address_if_valid("8080")`은 주소 문자열을 `Some`으로 감싸 반환합니다.
숫자가 아닌 `"rust"`나 `u16`의 범위를 벗어난 `"70000"`은 모두 `None`이 됩니다.
`.ok()`가 오류 정보를 버렸으므로 호출한 쪽에서는 두 실패 이유를 구분할 수 없습니다.
실패 이유를 알려야 한다면 `Option` 대신 `Result`를 반환하도록 함수를 작성하세요.

## Result를 반환하는 함수에서 ? 쓰기

이번에는 문자열 대신 `Option<u16>`으로 포트 번호를 받습니다.
설정한 포트 번호가 있으면 `Some`, 없으면 `None`입니다. 포트 번호가 없을 때
오류를 알려 주도록 `Result`를 반환합니다.
이 함수에서는 `Option`에 `?`를 바로 붙일 수 없습니다. `ok_or`나 `ok_or_else`로
`None`일 때 반환할 오류를 정해 `Result`로 바꾼 뒤 `?`를 사용해야 합니다.

다음 함수는 포트 번호가 있으면 접속 주소를 만들고, 없으면 오류를 반환합니다.
변환 전후의 타입을 볼 수 있도록 `ok_or`와 `?`를 두 줄로 나누었습니다.

```rust
{{#rustdoc ../../../examples/14_question_mark.rs item=listen_address}}
```

`ok_or`가 `Some(8080)`을 `Ok(8080)`으로, `None`을
`Err("포트를 설정해야 합니다")`로 바꾸면 `port_result`는 `Result`가 됩니다.
그다음 `?`는 `Ok`에서 포트 번호를 꺼내거나, `Err`를 현재 함수의 반환값으로
돌려보냅니다. 오류가 나면 주소를 만드는 마지막 줄은 실행하지 않습니다.

따라서 `listen_address(Some(8080))`은 주소 문자열을 `Ok`로 감싸 반환하고,
`listen_address(None)`은 `Err("포트를 설정해야 합니다")`를 반환합니다.
실제 코드에서는 앞 장의 `required_port`처럼 `port.ok_or("포트를 설정해야 합니다")?`로
한 줄에 이어 써도 됩니다.

## Result의 오류 타입이 다를 때 맞추기

`Option`과 `Result`를 맞추었다면, 이번에는 `Result` 안의 오류 타입을 살펴봅시다.
`parse::<u16>()`의 오류는 `std::num::ParseIntError`이지만, 다음 함수는 오류 메시지를
`String`으로 반환합니다. `map_err`로 오류를 문자열로 바꾼 뒤 `?`를 사용합니다.

```rust
{{#rustdoc ../../../examples/14_question_mark.rs item=parse_listen_address}}
```

첫 번째 `port_result`는 `Result<u16, std::num::ParseIntError>`이고,
두 번째 `port_result`는 `Result<u16, String>`입니다. `map_err`는 `Ok`의 포트 번호를
그대로 두고, `Err` 안의 오류만 입력값과 원래 오류 설명을 담은 문자열로 바꿉니다.
그다음 `?`가 포트 번호를 꺼내거나 함수에서 오류 문자열을 반환합니다.

`parse_listen_address("8080")`은 주소 문자열을 `Ok`로 감싸 반환합니다.
`"rust"`나 `"70000"`을 넣으면 실패한 입력과 이유를 담은 `Err`가 반환됩니다.
원래 오류의 설명은 남지만, 오류 값 자체는 문자열로 바뀝니다.

오류 타입이 다르다고 항상 `map_err`가 필요한 것은 아닙니다. 반환할 오류 타입에
원래 오류를 받는 `From` 구현이 있으면 `?`가 그 변환을 수행합니다.
`ParseIntError`를 `String`으로 바꾸는 `From` 구현은 없으므로 위 예제에서는
`map_err`로 직접 변환했습니다. 다음 예제에서는 오류를 자동으로 변환하는 경우를
살펴봅니다.

## From으로 오류를 자동 변환하기

이번에는 오류를 문자열로 바꾸는 대신 `AddressError`라는 열거형에 담습니다.
`From<ParseIntError>`를 구현해 정수 변환 오류를 `AddressError::InvalidPort`에
담는 방법을 정해 두면, `?`가 이 구현을 이용해 오류를 변환합니다.
지금은 구현 문법을 모두 익히기보다, 아래 함수에서 `map_err` 없이 `?`를 쓸 수 있는
이유에 집중하세요.

```rust
{{#rustdoc ../../../examples/14_question_mark.rs item=AddressError..parse_address_with_from}}
```

`parse::<u16>()`이 성공하면 `?`는 포트 번호를 꺼냅니다. 실패하면
`AddressError::from(error)`로 오류를 바꾸고 `Err`로 감싸 현재 함수에서 반환합니다.
따라서 `parse::<u16>()`을 호출할 때마다 `map_err(AddressError::InvalidPort)`를
붙이지 않아도 됩니다.
원래 `ParseIntError`도 열거형 안에 남으므로, 호출한 쪽에서 실패 이유를 확인할 수 있습니다.

오류를 한 곳에서만 변환한다면 `map_err`를 쓰는 편이 간단할 수 있습니다.
`From`은 여러 호출에서 발생하는 오류를 공통 오류 타입으로 변환할 때 유용합니다.
파일 읽기 오류와 정수 변환 오류도 각각 같은 오류 타입으로 바꾸는 `From` 구현이
있으면 `?`로 변환해 반환할 수 있습니다. 이때도 처음 오류가 발생한 곳에서 함수가
끝납니다.

> `From`은 한 타입의 값을 다른 타입의 값으로 바꾸는 방법을 정하는
> 트레이트<sub>trait</sub>입니다. `From`과 `Into`의 자세한 사용법과 구현 방법은
> 후속 강의에서 다룹니다. 여기서는 `?`가 오류를 변환할 때 `From` 구현을
> 사용할 수 있다는 점을 기억하세요.
