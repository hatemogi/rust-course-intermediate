# `Result` 이해하고 처리하기

## 성공과 실패 표현하기

```rust
enum Result<T, E> { Ok(T), Err(E) }
```

`Ok(T)`는 성공했을 때의 값을, `Err(E)`는 실패했을 때의 이유를 담습니다.
`Result`를 반환하는 함수는 반환형으로 실패 가능성을 나타내고, 실패했을 때는
그 이유를 `Err`에 담아 돌려줍니다.

## `Ok`와 `Err` 직접 반환하기

다음 나눗셈 함수는 계산이 가능하면 `Ok(몫)`을, 계산할 수 없으면
이유를 담은 `Err`를 반환합니다.

```rust
{{#rustdoc ../../../examples/07_result_mental_model.rs item=divide}}
```

`divide(12, 3)`은 `Ok(4)`를 반환합니다. `divide(12, 0)`은
`Err("0으로 나눌 수 없습니다")`를 반환합니다.
`i32::MIN`을 `-1`로 나누면 양수가 된 결과가 `i32`의 최댓값을 넘으므로,
이 경우에도 계산 전에 `Err`를 반환합니다.

값이 없다는 사실만 중요하면 `Option`을 쓰고, 호출자가 실패 이유까지 알아야
한다면 `Result`를 쓰세요.

## `unwrap()`으로 성공한 값 꺼내기

`Result<T, E>`의 `unwrap()`은 `Ok(value)`이면 안의 `value`를 반환합니다.
반환형은 `T`입니다. `Err(error)`이면 오류 값을 포함한 메시지와 함께
패닉<sub>panic</sub>을 일으킵니다. 오류를 복구하거나 기본값으로 바꾸지는 않습니다.

```rust
{{#rustdoc ../../../examples/07_result_mental_model.rs body=unwrap_result}}
```

`expect("설명")`도 `Ok`에서 값을 꺼내지만, `Err`일 때 패닉 메시지에
직접 쓴 설명과 오류 값을 함께 담습니다. 두 메서드는 호출한 `Result`를 소비하며,
성공 값이 `String`처럼 복사되지 않는 타입이면 그 값의 소유권도 꺼내 옵니다.

`unwrap`과 `expect`는 반드시 성공한다고 보장할 수 있거나, 실패하면 테스트를
바로 중단하려는 경우에 사용하세요. 사용자 입력이나 파일 읽기처럼 실제로
실패할 수 있는 작업은 `match`로 오류를 처리하거나, 뒤에서 배울 `?`로
호출자에게 오류를 돌려주는 편이 좋습니다.

## `match`로 성공과 실패 처리하기

성공했을 때와 실패했을 때 서로 다른 작업을 해야 한다면
패턴 매칭<sub>pattern matching</sub>으로 두 경우를 나누어 처리할 수 있습니다.
`match`를 쓰면 `Ok`와 `Err`를 모두 다루었는지 컴파일러가 확인해 줍니다.

성공하면 포트 번호를 사용하고, 실패하면 오류를 출력한 뒤 기본 포트로 대체합니다.
