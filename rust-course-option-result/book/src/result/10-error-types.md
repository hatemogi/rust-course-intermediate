# 오류 종류를 열거형으로 구분하기

`Result<T, E>`의 `E`에는 직접 만든 열거형도 쓸 수 있습니다. 오류 메시지만
반환하면 호출하는 쪽에서 메시지를 읽고 오류의 종류를 판단해야 합니다.
열거형으로 구분하면 앞 강의에서 배운 패턴을 사용해 오류마다 다르게 처리할 수 있습니다.

## 실패 이유를 타입으로 나타내기

설정이 없는 경우와 설정을 숫자로 바꾸지 못한 경우를 구분합니다. 숫자 변환 중에 생긴
오류는 열거형의 해당 항목에 담아 두므로 구체적인 원인도 확인할 수 있습니다.

`ok_or`는 `None`을 오류로 바꿉니다. `map_err`는 숫자 변환 오류를 `InvalidPort` 안에
담습니다. `?`를 만나기 전에 오류 타입을 맞추었으므로 자동 타입 변환을 몰라도
각 단계에서 어떤 오류를 반환하는지 알 수 있습니다.

## 오류에 추가 정보 담기

열거형으로 오류의 종류를 구분했다면, 이번에는 구조체로 오류가 발생한 곳의
정보를 함께 담아 봅시다. 파일을 읽지 못했을 때는 어떤 파일을 읽으려 했는지도 알아야 합니다. 파일을 읽는
함수를 호출한 곳에서 `map_err`를 사용해 원본 오류와 파일 경로를 구조체에 함께

`map_err`에 넘긴 클로저<sub>closure</sub>는 오류가 발생했을 때만 실행됩니다.
파일 경로를 `String`으로 복사해 보관하므로 함수 호출이 끝난 뒤에도
어떤 파일을 읽지 못했는지 확인할 수 있습니다.

`Result`의 오류 타입으로 쓰기 위해 반드시 `Error` 트레이트<sub>trait</sub>를
구현해야 하는 것은 아닙니다. 오류 메시지를 표시하고 원인을 연결하는 표준적인
방법과 위 예제의 `Display`, `Error` 구현은 트레이트와 `From`/`Into`를
배운 뒤 다룰 예정입니다.
