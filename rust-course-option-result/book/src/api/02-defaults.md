# 기본값과 지연 평가

## `unwrap()`으로 안의 값 꺼내기

`Option<T>`의 `unwrap()`은 `Some(value)`이면 안의 `value`를 반환합니다.
반환형은 `Option<T>`가 아닌 `T`입니다. `None`이면 기본값을 반환하는 대신
패닉<sub>panic</sub>을 일으켜 현재 실행 흐름을 중단합니다.

```rust
{{#rustdoc ../../../examples/02_defaults.rs body=unwrap_option}}
```

`expect("설명")`도 값을 꺼내는 동작은 같지만, `None`일 때 표시할 패닉 메시지에
직접 쓴 설명을 더할 수 있습니다. 값이 있어야 하는 이유를 적으면 문제를 찾는 데
도움이 됩니다. `unwrap()`과 `expect()`는 호출한 `Option`을 소비하므로,
안에 `String`처럼 복사되지 않는 값이 있으면 그 값의 소유권도 꺼내 옵니다.

`unwrap`과 `expect`는 값이 반드시 있음을 보장할 수 있거나, 테스트에서 값이
없을 때 바로 실패하게 하려는 경우에 사용하세요. 사용자 입력처럼 값이 없을 수
있는 상황에서는 `match`로 처리하거나 기본값을 정하는 편이 좋습니다.

## 값이 없을 때 기본값 사용하기

`unwrap_or`에 넘긴 기본값은 `Option`의 상태와 상관없이 먼저 계산됩니다.
`unwrap_or_else`는 값이 `None`일 때만 클로저<sub>closure</sub>를 실행합니다.

`|| 3000`은 인자 없이 호출하면 `3000`을 반환하는 클로저입니다. 기본값을 미리
계산해서 넘기는지, 필요할 때 계산할 함수를 넘기는지가 두 메서드의 차이입니다.

```rust
{{#rustdoc ../../../examples/02_defaults.rs body=defaults}}
```

예제의 `&mut default_port`는 같은 클로저를 빌려서 전달합니다. 첫 번째 예제에서는
`Some`이어도 호출 횟수가 늘고, 두 번째 예제에서는 `None`일 때만 늘어납니다.

## 기본값은 언제 계산할까?

| 호출 | `Some`일 때 | `None`일 때 |
| --- | --- | --- |
| `unwrap_or(default_port())` | 기본값을 계산하지만 사용하지 않음 | 계산한 기본값을 사용 |
| `unwrap_or_else(default_port)` | 기본값 함수를 호출하지 않음 | 함수를 호출해 기본값을 구함 |

두 메서드 모두 `Some`이면 그 안의 값을 반환합니다. 차이는 기본값을 계산하는 시점입니다.
