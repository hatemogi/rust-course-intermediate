# `cargo tree`로 의존성 관계 찾기

의존성이 많아지면 `Cargo.toml`만 보고 실제 빌드에 포함되는 패키지를 모두 알기
어렵습니다. `cargo tree`는 Cargo가 계산한 의존성 관계를 트리로 보여 줍니다.

```bash
cargo tree
```

들여쓰기는 어떤 패키지가 다른 패키지를 가져왔는지를 나타냅니다. 같은 의존성
하위 구조가 이미 출력됐다면 Cargo는 `(*)`를 붙이고 반복해서 펼치지 않습니다.

## 특정 의존성이 들어온 경로 찾기

예상하지 않은 패키지가 보이면 관계를 거꾸로 출력합니다.

```bash
cargo tree -i serde
```

`-i`는 지정한 패키지를 사용하는 상위 의존성을 보여 줍니다. 직접 추가하지 않은
패키지가 어떤 경로로 들어왔는지 찾을 때 유용합니다.

여러 버전이 함께 포함된 패키지만 확인하려면 다음 명령을 사용합니다.

```bash
cargo tree --duplicates
```

같은 패키지의 여러 버전이 항상 오류인 것은 아닙니다. 하지만 빌드 시간과 실행 파일
크기가 늘어날 수 있으므로, 오래된 버전을 요구하는 상위 의존성을 갱신할 수 있는지
살펴볼 근거가 됩니다.

## 활성화된 feature 찾기

어떤 의존성 feature가 켜졌는지 보려면 관계 종류를 `features`로 지정합니다.

```bash
cargo tree -e features
cargo tree -e features -i serde
```

첫 번째 명령은 전체 feature 관계를 보여 줍니다. 출력이 길다면 두 번째 명령처럼
패키지를 지정해 어떤 경로에서 feature가 활성화됐는지 거꾸로 살펴봅니다.

`cargo tree`의 결과는 실제 빌드 관계를 이해하는 데 가깝지만, 플랫폼과 빌드
종류처럼 컴파일에 영향을 주는 모든 조건을 완전히 재현한 것은 아닙니다. 명령의
옵션과 출력 해석은 [Cargo의 `cargo tree` 문서](https://doc.rust-lang.org/cargo/commands/cargo-tree.html)에서
확인할 수 있습니다.
