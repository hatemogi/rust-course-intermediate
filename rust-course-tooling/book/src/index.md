# 우아한 Rust 중급: 개발 도구

코드를 작성한 뒤에는 형식을 맞추고, 의심스러운 부분을 찾고, 동작을 테스트하고,
성능에 관한 주장을 측정해야 합니다. 이 교재에서는 Rust 프로젝트에서 자주 사용하는
`rustup`, `cargo check`, `rustfmt`, Clippy, 의존성 관리, `cargo doc`,
`cargo test`와 `cargo bench`를 하나의 개발·검증 흐름으로 익힙니다.

도구의 출력을 무조건 따르는 방법을 배우지는 않습니다. 자동 도구가 무엇을 확인할
수 있는지 구분하고, 제안을 적용하거나 적용하지 않을 근거를 코드의 목적과 테스트,
측정 결과로 설명하는 것이 이 강의의 목표입니다.

## 학습 목표

이 교재를 마치면 다음 작업을 할 수 있습니다.

- rustup으로 도구 체인, 구성 요소와 컴파일 대상을 확인하고 관리합니다.
- `rust-toolchain.toml`로 프로젝트가 사용할 Rust 버전과 도구를 선언합니다.
- `rust-toolchain.toml`과 `Cargo.toml`의 `rust-version`이 맡는 역할을 구분합니다.
- Cargo 타깃을 구분하고 `cargo check`의 검사 범위를 지정합니다.
- 컴파일 오류의 코드, 위치, `note`와 `help`를 순서대로 읽습니다.
- `cargo fmt`와 `cargo fmt --check`의 쓰임을 구분합니다.
- Clippy를 모든 Cargo 타깃에 실행하고 lint 설명을 읽습니다.
- 교육용 코드나 의도적인 구현에서 lint를 제한적으로 허용하고 이유를 남깁니다.
- VS Code와 Zed에서 저장할 때 rustfmt를 실행하고 Clippy 진단을 표시하도록
  설정합니다.
- `cargo fix`와 `cargo clippy --fix`가 바꾼 코드를 diff와 테스트로 검토합니다.
- `Cargo.toml`과 `Cargo.lock`의 역할을 구분하고 의존성을 제한적으로 갱신합니다.
- `cargo tree`로 의존성이 들어온 경로와 활성화된 feature를 찾습니다.
- 기본 구성, 기본 feature를 끈 구성과 모든 feature를 켠 구성을 각각 검사합니다.
- `cargo doc`으로 생성한 API 문서에서 공개 항목과 사용 흐름을 확인합니다.
- 기본 assertion을 사용하고 단위 테스트와 통합 테스트를 알맞은 위치에 작성합니다.
- 오류를 반환하는 테스트와 panic하거나 평소 제외한 테스트를 실행합니다.
- 공개 API의 사용법과 허용되지 않는 사용법을 문서 테스트로 검사합니다.
- 디버그 빌드에서 잰 시간을 성능 근거로 사용하면 안 되는 이유를 설명합니다.
- `std::hint::black_box`와 반복 측정으로 간단한 벤치마크를 작성합니다.
- 포맷, 린트, feature별 컴파일, 테스트, API 문서와 벤치마크 컴파일을 자동 검증
  명령으로 묶습니다.

Rust 기본 문법과 Cargo 프로젝트 구조를 알고 있다고 가정합니다.

목차에서 `◆`가 붙은 주제는 전체 동영상 과정에서 이어서 다룹니다.
