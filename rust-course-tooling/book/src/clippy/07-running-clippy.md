# 클리피 실행하고 결과 읽기

클리피<sub>Clippy</sub>는 컴파일되는 Rust 코드에서 실수일 가능성이 있는 표현, 불필요하게 복잡한
코드와 더 자연스러운 Rust 표현을 찾는 공식 린트<sub>lint</sub> 도구입니다.

```bash
cargo clippy
```

타깃 선택 옵션을 지정하지 않으면 선택한 패키지의 라이브러리와 실행 파일 타깃을
검사합니다. 예제, 통합 테스트, 벤치마크 타깃까지 검사하려면 다음 명령을 사용합니다.

```bash
cargo clippy --all-targets --locked -- -D warnings
```

- `--all-targets`는 카고<sub>Cargo</sub>의 모든 타깃을 검사합니다.
- `--locked`는 `Cargo.lock`을 임의로 바꾸지 못하게 합니다.
- `-- -D warnings`는 경고를 검사 실패로 취급합니다. `--` 뒤의 옵션은 rustc와
  클리피에 전달됩니다.

다음 예제는 `map`으로 각 숫자가 짝수인지를 계산한 뒤, `any`로 `true`가 하나라도
있는지 다시 확인합니다.

```rust
{{#include ../../../examples/07_clippy.rs}}
```

이 예제만 검사해 보세요.

```bash
cargo clippy --example 07_clippy --locked
```

클리피는 `clippy::map_all_any_identity` 린트를 표시하고 두 호출을 다음과 같이
`any` 하나로 합치라고 제안합니다.

```rust
numbers.iter().any(|number| number % 2 == 0)
```

이렇게 바꾸면 조건에 맞는 값이 있는지를 코드에서 바로 읽을 수 있고, 중간의
`bool` 값을 만들 필요도 없습니다.

린트가 나오면 이름과 설명, 지적한 코드 범위, 제안한 수정 내용을 차례로 읽으세요.
린트 이름으로 클리피 설명을 찾아보면 잘못 잡아낸 경우와 적용 시 주의점도 확인할 수
있습니다.

> **참고: 린트 도구란?**
>
> 린트 도구는 코드를 실행하지 않고 분석하여, 컴파일은 되지만 실수하기 쉽거나
> 불필요하게 복잡한 부분을 찾아냅니다. 이때 적용하는 검사 규칙 하나하나를
> **린트**라고 부릅니다. 린트를 모두 통과해도 프로그램이 요구 사항대로
> 동작한다는 뜻은 아니므로 테스트도 함께 실행해야 합니다.
