# Clippy 제안을 판단하는 기준

Clippy 제안은 강한 단서이지 프로그램의 요구 사항은 아닙니다. 다음 순서로 판단하면
좋습니다.

1. lint가 경고하는 실제 위험이나 낭비가 무엇인지 설명합니다.
2. 제안대로 바꿨을 때 동작과 공개 API가 그대로인지 확인합니다.
3. 관련 테스트를 실행합니다.
4. 적용하지 않는다면 가능한 한 좁은 범위에서 허용하고 이유를 적습니다.

예를 들어 `Vec::new()` 뒤에 `push`를 연이어 호출한 코드는 `vec![]`로 줄일 수
있습니다. 그러나 `Vec::push`를 처음 설명하는 교육용 예제라면 원래 코드가 목적에 더
맞을 수 있습니다.

```rust,ignore
#[allow(clippy::vec_init_then_push)] // Vec::new와 push를 단계별로 소개합니다.
fn push_example() {
    let mut values = Vec::new();
    values.push(10);
    values.push(20);
}
```

파일 전체나 프로젝트 전체에서 lint를 끄기 전에 함수나 모듈처럼 더 작은 범위에서
허용할 수 있는지 확인하세요. 이유 없는 `allow`는 이후의 실제 문제까지 숨깁니다.

## AI 코드 검토하기

AI가 Clippy 경고를 없애기 위해 `#[allow(clippy::all)]`을 추가했다면 경고가 해결된
것이 아닙니다. 원래 lint를 다시 실행하고, 각각 수정할지 제한적으로 허용할지
나누어 판단하세요.
