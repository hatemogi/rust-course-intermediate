# 리터럴·범위·OR 패턴

리터럴 패턴은 특정 값과 매칭<sub>matching</sub>되고, 범위 패턴은 연속된 값과
매칭됩니다. 범위 패턴은 숫자와 문자 값에 사용할 수 있습니다. `1..10`은 아래쪽
경계 `1`을 포함하고 위쪽 경계 `10`은 제외하지만, `1..=10`은 양 끝을 모두
포함합니다. `..0`이나 `100..`처럼 한쪽 경계를 생략할 수도 있습니다.

예제의 `..0`은 모든 음수와 매칭되고, `1..10`은 `1`부터 `9`까지의 한 자리

뒤의 `_`에는 `100` 이상의 정수만 남습니다.

## 빈 범위는 사용할 수 없음

범위 안에 값이 하나도 들어갈 수 없으면 빈 범위가 됩니다. 예를 들어 `5..=3`은
`5` 이상이면서 `3` 이하인 값을 요구하므로 어떤 정수와도 매칭될 수 없습니다.
`5..5`도 시작 값 `5`는 포함하지만 끝 값 `5`는 제외하므로 비어 있습니다. 반면
`5..=5`는 `5` 하나와 매칭되는 범위입니다. 빈 범위 패턴은 어떤 값과도 매칭되지
않아 쓸모가 없고 대개 경계를 잘못 적은 결과이므로 컴파일러가 오류로 알려 줍니다.

OR 패턴의 각 선택지에서는 값에 같은 이름을 붙여야 하며, 그 이름의 타입과
바인딩 방식도 같아야 합니다.
어느 선택지가 맞더라도 갈래의 본문에서 같은 바인딩을 사용할 수 있어야 하기
때문입니다. 패턴이 지나치게 길어지면 여러 갈래로 나누고 공통 함수를 호출하는
편이 읽기 쉬울 수 있습니다.

## `matches!`로 매칭 여부 확인하기

값이 특정 패턴과 매칭되는지만 필요하다면 `matches!` 매크로<sub>macro</sub>를
사용할 수 있습니다.

```rust
{{#rustdoc ../../../examples/05_ranges_or.rs body=is_confirmed}}
```

`matches!(value, pattern)`은 값이 패턴과 매칭되면 `true`, 매칭되지 않으면
`false`를 반환합니다. 내부적으로 같은 뜻의 `match` 식을 짧게 쓴 형태이며, 값에
이름을 붙여 뒤 코드에서 사용하는 용도는 아닙니다.

`assert!`는 패턴을 검사하지 않고 전달받은 불리언 값이 참인지 확인합니다. 따라서
`assert!(matches!(value, pattern))`에서는 `matches!`가 매칭 여부를 계산하고,
`assert!`가 그 결과가 참인지 검사합니다.
