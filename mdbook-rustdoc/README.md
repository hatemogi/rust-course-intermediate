# Rust 코드 이름으로 발췌하기

이 도구는 mdBook 전처리기입니다. Rust 소스를 `syn`으로 분석하고 함수·타입·구현의
위치를 찾아 원본 텍스트를 가져옵니다. 예제에는 발췌용 주석을 넣지 않습니다.
함수를 여러 개로 나눈 예제는 `main`에서 각 함수를 호출해 단언문까지 실행합니다.

패턴 강의부터 사용합니다. 기존 `{{#include ...}}`, 줄 번호, `ANCHOR`,
`{{#rustdoc_include ...}}`는 바꾸지 않으며 mdBook의 기본 전처리기가 계속 처리합니다.
파일 전체를 보여 줄 때는 기존 `{{#include 파일경로}}`를 그대로 씁니다.

## 연결하기

Rust·Cargo·mdBook이 필요합니다. 각 강의의 `book/book.toml`에 다음 설정을 둡니다.
경로는 이 저장소의 디렉터리 구조를 기준으로 합니다.

```toml
[preprocessor.rustdoc-excerpt]
command = "sh ../../mdbook-rustdoc/run.sh"
before = ["links"]
```

`run.sh`는 잠금 파일에 고정된 의존성으로 도구를 빌드하고 실행합니다. 첫 실행에는
의존성 다운로드가 필요할 수 있습니다. 공통 도구는 다른 강의의 파일을 참조하지
않으며, 각 강의에서 `make check`, `make mdbook`, `make mdslide`로 사용할 수 있습니다.
강의를 별도 저장소로 옮길 때는 이 도구도 함께 설치하고 설정의 경로를 맞춥니다.

## 발췌 문법

`{{#rustdoc ...}}`는 이 도구가 추가하는 문법이며 mdBook의 기본 문법은 아닙니다.
파일 경로는 지시문을 쓴 Markdown 파일에서 시작하는 상대 경로입니다.
아래 지시문은 교재의 Rust 코드 블록 안에 넣습니다.

```text
{{#rustdoc ../../../examples/07_hashmap.rs item=basic}}
{{#rustdoc ../../../examples/07_hashmap.rs body=basic}}
```

- `item=basic`은 함수의 속성·선언·본문을 가져옵니다.
- `body=basic`은 함수의 중괄호 안쪽을 가져오고 공통 들여쓰기를 제거합니다.
- `statements=boundary`는 함수 본문에서 마지막 반환 표현식을 제외합니다. 퀴즈에
  계산 코드만 보여 주고, 반환값의 단언문은 `main`에서 실행할 때 사용합니다.
  세미콜론 없는 마지막 표현식만 제외하며, 중간의 `return` 문은 그대로 둡니다.
- `item=Priority`처럼 구조체·열거형·트레이트 이름도 지정할 수 있습니다.
- `item=impl:fmt::Display:Priority`는 특정 트레이트 구현을 가져옵니다.
- `item=impl:TextBox`는 해당 타입의 고유 메서드 구현을 가져옵니다.
- `item=TextBox..impl:DerefMut:TextBox`는 두 항목을 포함한 연속 구간을 가져옵니다.
  중간 주석과 빈 줄도 포함됩니다.
- `item=use:std::num::ParseIntError..sum`처럼 `use` 구문부터 함수까지 지정할 수도
  있습니다. `use` 뒤에는 원본의 가져오기 경로를 공백 없이 적습니다.

이름은 파일 최상위 항목에서 찾습니다. 모듈 안의 항목이나 개별 메서드는 현재
지원하지 않습니다. 이름이 없거나 같은 이름이 여러 개면 빌드를 실패시킵니다.
구현 이름에 제네릭 인자가 있으면 `impl:From<&str>:UserName`처럼 함께 적습니다.
공백이 들어 있는 파일 경로와 선택자는 현재 지원하지 않습니다.

속성과 문서 주석은 항목에 포함됩니다. 항목 앞의 일반 주석은 포함되지 않으며,
함수 본문이나 연속 구간 안에 있는 일반 주석은 보존합니다. 코드를 다시 생성하지
않으므로 원본의 문자열·주석·서식이 그대로 유지됩니다. 함수 본문은 들여쓰기만
정리합니다. 발췌한 코드에 필요한 `use`나 다른 타입을 자동으로 추가하지는 않습니다.

## 검사하기

```bash
make -C mdbook-rustdoc check
```

구문 분석 검사는 한국어·원시 문자열·수명·중첩 주석·속성·구현·누락된 이름을
확인합니다. 실제 mdBook 검사에서는 한 장에 기존 앵커·줄 번호·`rustdoc_include`와
새 문법을 함께 넣어 빌드하고, 잘못된 이름이 빌드를 실패시키는지도 확인합니다.
mdBook 0.4와 0.5의 입력 구조를 읽을 수 있습니다.
