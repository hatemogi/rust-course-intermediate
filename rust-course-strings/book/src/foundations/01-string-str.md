## `&String`은 무엇을 빌리는가

`&String`은 `String` 값 자체를 빌린 참조입니다. 힙의 문자열 데이터를 새로
복사하거나 소유하지 않으며, 참조가 유효한 동안 원래 `String`도 다른 곳으로
이동하지 않습니다. 공유 참조이므로 `push_str`처럼 문자열을 바꾸는 메서드는
호출할 수 없습니다.

| 타입 | 소유하거나 빌리는 대상 | 만들 수 있는 값 |
|---|---|---|
| `String` | 힙의 UTF-8 문자열을 소유함 | 새 소유 문자열 |
| `&String` | `String` 값 전체를 빌림 | `String`에서 빌린 참조 |
| `&str` | UTF-8 문자열의 연속된 영역을 빌림 | 문자열 리터럴, `String` 전체나 일부를 빌린 슬라이스 |

`String`은 문자열 슬라이스인 `str`을 역참조 대상으로 삼습니다. 따라서 Rust는
필요한 곳에서 `&String`을 `&str`로 자동 변환합니다. 이를 역참조 강제
변환<sub>deref coercion</sub>이라고 합니다.

```rust
{{#include ../../../examples/01_string_str.rs:string_reference}}
```

`string_reference`는 `String` 값 전체를 가리키지만, `whole_slice`는 그 안의
문자열 전체를 가리킵니다. `partial_slice`처럼 `&str`은 문자열의 일부만 가리킬
수도 있습니다. `greet`가 `&str`을 받더라도 `&String`을 넘길 수 있는 까닭은
호출 시점에 역참조 강제 변환이 일어나기 때문입니다.

## 함수가 받을 타입 정하기

함수가 문자열을 읽기만 한다면 보통 `&str`을 받습니다. 그러면 호출자는 문자열 리터럴과
`String` 전체나 일부를 모두 넘길 수 있습니다. 하지만 매개변수를 `&String`으로 정하면
호출자는 반드시 `String`을 준비해야 하므로 문자열 리터럴이나 다른 `&str`을 바로
넘길 수 없습니다. 함수가 입력을 저장하거나 수정해야 한다면 `String`을 소유해야
하는지, `&mut String`을 받아야 하는지 따로 검토합니다.

| 함수가 문자열로 하는 일 | 매개변수 타입 | 선택하는 이유 |
|---|---|---|
| 내용을 읽기만 함 | `&str` | 문자열 리터럴, `String` 전체나 일부를 모두 받을 수 있음 |
| 내용을 제자리에서 바꿈 | 주로 `&mut String` | `push`, `truncate`처럼 문자열 길이를 바꾸는 메서드도 호출할 수 있음 |
| 호출 뒤에도 보관하거나 소유해야 함 | `String` | 호출자에게서 소유권을 넘겨받아 함수 밖이나 구조체에 저장할 수 있음 |
| `capacity`처럼 `String` 자체의 정보를 읽음 | `&String` | 문자열 내용이 아니라 버퍼를 관리하는 `String` 값을 직접 빌려야 함 |

따라서 일반적인 읽기 전용 문자열 매개변수에는 `&str`을 먼저 고려합니다.
`&String`은 함수가 `String` 값 자체를 다뤄야 할 때만 사용합니다.
